## Fixed operation

`argv.json` contains the exact proposed JSON argument array. The environment begins empty and supplies PATH, HOME, LC_ALL, LANG, and TZ. The ordinary interpreter uses `-I -S -B`. The helper accepts exactly one operation and one fixed output directory. It does not import dbus, gi, candidate owners, archived sources, or native libraries. The helper archives file buffers in the exclusive `inputs.raw` file. Each captured regular-file row records its archive offset, size, SHA-256, and descriptor-checked metadata. It records directory names, links, aliases, and absences separately. Hashes describe the archived buffers. The archive is data, never executable input to this operation. All successful and partial output stays in place. An existing output directory refuses first use. No retry or cleanup is proposed.

The helper enforces 268435456 bytes per file, 1073741824 archived input bytes in total, 25000 records, 25000 names per directory, 4096 bytes per link or ELF string, 8388608 generated JSON bytes in total, 120 seconds checked wall time, a 120-second alarm, and CPU limits of 120/122 seconds. ## Data shape and source grounding

The organizing structure is one path-indexed record map, a distinct actor-candidate set, and a recursive ELF dependency graph. The archive corpus includes all regular bytes under the actual isolated stdlib roots, including eligible and optimization bytecode. It prunes unrelated `site-packages`, then adds complete dbus/gi packages and their actual installed metadata directories explicitly. Full standard-library ELF bytes are archived without treating all of them as runtime actors or resolving unrelated extensions' dependencies.

The three actual isolated search entries are `/usr/lib64/python314.zip`, `/usr/lib64/python3.14`, and `/usr/lib64/python3.14/lib-dynload`. The zip is currently absent. The installed `pkgutil.extend_path` scans these entries and trusts `gi.pkg` portions. The helper captures the corresponding gi/dbus directories and `.pkg` files, or their absences. These paths are absent in current ordinary metadata reads. A later appearance is evidence requiring root review, not automatic permission to execute a portion. The helper currently archives a discovered `.pkg` but does not chase its arbitrary contents.

Installed gi imports `pkgutil.extend_path`, `_gi.Repository`, `Repository.get_default`, and maintained import machinery. `gi.module` uses `get_typelib_path`. `gi.importer` and `gi.overrides` choose namespaces and overrides dynamically. `PYGI_OVERRIDES_PATH` changes override lookup. The proposed empty environment excludes it and GI_TYPELIB_PATH, LD_LIBRARY_PATH, LD_PRELOAD, OPENSSL_CONF, and OPENSSL_MODULES; the effective environment is recorded rather than inferred. GI library default directory selection remains unobserved. The helper captures default-directory candidates and the GLib, GObject, Gio, and GModule companion typelibs. All overrides are archived with gi. This is a conservative byte corpus and metadata proposal, not a typelib selection observation.

Actor candidates come from the actual fixed entry, observer, client, holder fixture, job adapter, tests, and wrappers. They include Python, env, timeout, printf, and bash, the explicit dbus/gi bindings, and stdlib extensions needed by hashing, JSON, subprocess, unittest/mock, resource, tempfile, socket, typing, GLib overrides, and their likely transitive support. The declared extension set is conservative static preparation, not an observed import list. `actor_candidates` and `runtime_selection_observed=false` keep that distinction explicit. Native daemon binaries in the existing 31-row map are archive inputs for proof stability; this helper does not infer that ordinary imports execute them.

The helper parses actual ELF64 x86-64 program headers and dynamic tags. It preserves DT_NEEDED, PT_INTERP, RPATH, and RUNPATH. It parses the installed new glibc loader cache format and records its flags and hwcap fields. It recursively captures matching x86-64 cache candidates and fixed search candidates, plus search-directory and glibc-hwcaps membership. It does not label its candidate enumeration as the actual loader's selected image. RPATH inheritance, exact cache ranking and CPU hwcap selection remain root audit work. Unknown path expansions and unresolved dependencies refuse. Other architectures are excluded from recursive cache candidates.

The proposal also captures actual loader conf.d contents, preload presence or absence, the whole locale archive, locale data, public NSS configuration and data, selected NSS modules, OpenSSL configuration, its two actual includes, and provider-directory membership. Current NSS selects files/systemd, myhostname, mdns4_minimal, resolve, and dns. No shadow or gshadow bytes are read. Configured future includes or default-library paths are not silently accepted by this fixed operation. No denied actor files, sudo bytes, private caches, or credentials are part of this package.
